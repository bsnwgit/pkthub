Platform Overview

Three areas. One shell.

pktHub provides three distinct platform areas through a single unified interface — manage apps, operate through them, and build wall displays from their data.

App Manager

Register & control

Register and deregister pktAPP apps. Toggle observe vs managed mode. Monitor health, rotate suite-tokens, and manage the app registry from one place.

Managed App Viewer

Proxied access

Proxied pktAPP UI served inside the pktHub shell. A thin 44px top bar stays persistent — the pktAPP app gets the full viewport. No double-nav. No clutter.

Kiosk Builder

Wall displays

Drag-and-drop widget composer for NOC/SOC displays. Build layouts from any registered app's widgets. Publish with a signed URL token — no login required on the display monitor.

Registration & Lockdown

Observe first. Lock down when ready.

Two-phase registration prevents disruption. Validate everything through pktHub before enabling the token lockout.

1

Register

Add pktAPP to pktHub registry. Handshake via /api/suite/register. API version negotiated via X-Suite-Version header.

2

Observe Mode

pktHub monitors and proxies. Direct pktAPP access still works. Operator validates everything before flipping.

3

Managed Mode

Suite-token lockout active. Every request to pktAPP must carry X-Suite-Token. No token = 403.

4

Deregister / Break-Glass

Full clean break. Token removed, direct access restored, pktAPP local users un-dormanted. --emergency-unlock CLI on each pktAPP for when pktHub is unreachable.

Wall displays. No login required.

Build, publish, and display NOC/SOC dashboards on any monitor without operator credentials sitting on screen.

Widget Manifests

Auto-populated library

Each pktAPP exposes /api/widgets/manifest declaring available widgets, data schemas, refresh rates, and required permissions. pktHub reads this at registration and populates the builder library automatically.

Drag-and-Drop Composer

Grid canvas

Widget library panel per registered app. Widget borders colored by source app. Arrange freely, save named layouts. Per-dashboard mode: static live-refresh or rotating slides with configurable dwell time.

Signed Display Tokens

Publish & display

Published kiosks get a URL-based signed display token. Wall monitor loads once, auto-refreshes, no operator login required. Tokens are revocable from pktHub at any time.

Architecture

How it connects

pktHub sits between users and all pktAPP apps. In managed mode every request flows through the suite-token layer — direct access is blocked.

Build Plan

Two tracks. One rollout.

Track 1 builds pktHub. Track 2 adds the required hooks to each existing pktAPP app.

Track 1 — pktHub Application

  • FastAPI backend — reverse proxy, JWT auth, Okta/OIDC, app registry API, kiosk builder API
  • React frontend — App Manager, Proxied App Viewer (44px top bar shell), Kiosk Builder, Dashboard, Settings, Users
  • SQLite WAL DB — app registry, users, kiosk layouts (JSON), audit log, notification settings, platform config
  • Audit log — stored in pktHub DB only; no forwarding to pktLog (prevents circular dependency)
  • API versioning — X-Suite-Version header on all pktHub↔pktAPP calls; version negotiated at registration
  • Systemd service — port 8760 HTTPS, auto-restart hardened

Track 2 — Changes to Each pktAPP

  • Suite-token middleware — validates X-Suite-Token header; 403 if invalid in managed mode
  • Break-glass CLI — --emergency-unlock triggers full deregister; logged and alerted in pktHub
  • /api/widgets/manifest — declares kiosk widgets, data schemas, refresh rates, permissions
  • Registration endpoints — /api/suite/register and /api/suite/deregister
  • API versioning — advertise supported X-Suite-Version at registration
  • Local users dormant — users table stays in place; fully restored on deregister
Server

pkt server · Port 8760

Same server as all pktAPP apps. Shared infrastructure, isolated systemd services, SQLite WAL at pkthub.db.

Deploy Pattern

Identical to pktFlow / pktLog

SFTP source → build frontend in Linux /tmp → cp dist to app dir → systemctl restart. deploy.py script handles the full cycle.

SSH Note

Python + Paramiko only

SentinelOne blocks system ssh.exe. All remote ops via Paramiko through Desktop Commander. One script, one run, no retry loops.

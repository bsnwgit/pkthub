Administrator Overview

The Admin role has unrestricted access to all features in pktLog. Administrators are responsible for the health of the platform, the security of user accounts, and the correctness of ingest configuration.

Admin accounts should be limited to personnel who require configuration and user management rights. Operational log review tasks should use the Analyst role.

User Management

Navigate to Settings → Users to manage all user accounts. The admin who installs the platform has the initial admin account; additional users are created here.

Creating a User

  1. Open Settings → Users in the top navigation.
  2. Click "New User" to open the creation form.
  3. Enter username and email — usernames must be unique and lowercase.
  4. Set a temporary password — the user should change this on first login.
  5. Assign a role: Admin, Analyst, or Viewer. Choose the least-privilege role that fits the user's responsibilities.
  6. Click Create. The user can log in immediately.

Collector Registry

The collector registry maps sending IPs to human-readable names, sites, and groups. This enrichment is applied at normalize time — every event from a registered collector receives the correct collector_name, site, and group_name fields.

Adding a Collector

Navigate to Settings → Collectors and click "Add Collector". Enter the sending IP address, a display name, the site label, and an optional group name. Save — enrichment applies to all subsequent events from that IP.

Unknown Collectors

Any IP sending syslog that is not in the registry appears in the Unknown Collectors panel. Options:

  • → Register it — click the IP to open the registration form. Future events will be enriched.
  • → Dismiss it — suppresses alerts about this source without adding it to the registry. Useful for known-good sources that don't need enrichment.

Collector Health Monitoring

The Dashboard shows last-seen timestamps for all registered collectors. A collector that has not sent events within its configured silence threshold will generate a collector_silence alert if that rule is enabled.

Alert Rules

Navigate to Alerts → Rules to create and manage alert rules. Rules are evaluated by the alert engine on a configurable interval.

Available Rule Types

TypeWhat It DetectsKey Parameters
severity_thresholdEvents at or above a severity level exceed a count in a time windowSeverity, count, window (minutes)
collector_silenceA registered collector stops sending events for a defined periodCollector name, silence duration
new_collectorAn unrecognized IP sends syslog for the first timeNone — fires on any unknown source
rate_spikeCurrent event rate exceeds the rolling baseline by a multiplierMultiplier (e.g. 3×), baseline window (days)
keyword_matchA regex pattern appears in the message field within a windowRegex pattern, window, minimum count
host_patternEvents from a specific host or host pattern exceed a thresholdHost regex, severity, count, window

Alert Lifecycle

When an alert rule fires, an event is created in the Alerts → Events view. Analysts and admins can acknowledge events (marks them reviewed without closing) or resolve them (marks them closed). Resolved events are retained for the configured retention period then purged.

Start with new_collector and collector_silence rules to ensure your ingest pipeline is healthy before adding content-based rules.

Settings → SSL / TLS

pktLog auto-detects SSL on startup. To enable HTTPS, go to Settings → Integrations → SSL/TLS and upload either a PFX/P12 bundle or a PEM certificate + private key pair. A service restart is required to apply the new certificate. The restart button is in Settings → System.

Settings → Storage

The storage backend defaults to ClickHouse. The Manual Cleanup button triggers an immediate TTL purge outside of ClickHouse's automatic merge schedule — use this after dramatically shortening retention to reclaim disk space promptly.

System Maintenance

Restarting the Service

Navigate to Settings → System → Restart Service. The UI will show a loading state while the service restarts (~5 seconds). After restart, connected collectors will automatically reconnect and resume sending events.

Backup

pktLog maintains a 2-revision rotating backup of all application data. Click Settings → System → Backup to trigger an immediate backup. The backup includes the SQLite database (users, settings, alert rules) and configuration. ClickHouse data is not included in this backup — use ClickHouse-native backup for event data.

Emergency Password Reset

If an admin account is locked out, the password can be reset directly in the SQLite database via the server CLI. Contact your server administrator and use the bcrypt reset procedure documented in the deployment runbook.

Always run a backup before performing upgrades, schema changes, or significant configuration modifications.

Security Guidance

Hardening Checklist

  1. Change the default secret key in config.yaml before first production login. Use a cryptographically random 32-byte hex string.
  2. Enable HTTPS before exposing the interface to any network. Upload a valid certificate via Settings → SSL/TLS.
  3. Restrict CORS origins in config to your dashboard's actual hostname.
  4. Limit Admin accounts to only those who need platform configuration rights. Operational staff should be Analyst or Viewer.
  5. Set a short token lifetime (120–240 minutes) for environments with sensitive log data.
  6. Restrict the ingest port (8761) at the firewall to only your collector host IPs — it should not be publicly accessible.
  7. Rotate the JWT secret key periodically. This invalidates all active sessions, requiring users to re-authenticate.

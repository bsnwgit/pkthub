Analyst Overview

The Analyst role provides read access to all log data plus the ability to search, filter, export, and acknowledge alerts. Analysts cannot modify platform configuration or manage users, but have full access to everything needed for incident investigation and compliance review.

Dashboard

The Dashboard is your starting point. It shows the live state of the syslog platform at a glance.

Use the time-range selector at the top of the dashboard to change the analysis window. All widgets update simultaneously.

Log Explorer

The Log Explorer (Logs in the navigation) is your primary tool for searching and investigating syslog events. It provides paginated access to all stored events with rich filtering.

Log Table Columns

ColumnDescription
TimestampEvent time (parsed from the syslog message, not server arrival time)
Received AtServer-side arrival timestamp — useful when device clocks are unreliable
HostSource device hostname or IP
SeverityColor-coded badge: Emergency (red) → Debug (gray)
FacilitySyslog facility (kern, auth, daemon, local0–local7, etc.)
ProgramApplication or process name (e.g. sshd, kernel, nginx)
MessageFull message body — click a row to expand and view structured fields
Site / CollectorEnrichment from the collector registry (if registered)

Row Detail View

Click any log row to expand it. The detail panel shows all 17 normalized fields including raw_message (the original unmodified syslog line), pid, msg_id, and any RFC 5424 structured data elements.

Search & Filters

The filter bar at the top of the Log Explorer lets you narrow results precisely. Filters are additive (AND logic).

Time Range

Last 15m, 1h, 6h, 24h, 7d, or custom start/end datetime

Host

Exact match or wildcard (e.g. fw-*, 10.0.*)

Severity

One or more severity levels via multi-select (e.g. emergency + critical + error)

Facility

Syslog facility (auth, kern, daemon, local0–local7, etc.)

Program

Application name (e.g. sshd, nginx, cron)

Site

Filter to events from a specific site (from collector registry)

Keyword Search

Full-text search within the message field. Supports regex.

Collector

Filter to events from a specific registered collector IP or name

Combine Severity: error+critical+emergency with a short time window to quickly surface all high-priority events during an incident.

Export Data

Analysts can export filtered log results to CSV or JSON for use in external tools, incident reports, or compliance evidence packages.

How to Export

Apply your desired filters in the Log Explorer, then click the Export button in the toolbar. Choose CSV (for spreadsheet analysis) or JSON (for programmatic processing). The export includes all currently filtered results up to the configured export limit.

Export Fields

Exports include all 17 normalized fields: received_at, event_time, host, severity, facility, priority, program, pid, message, raw_message, collector_ip, collector_name, site, group_name, msg_id, structured_data, ingest_id.

Alert Review

Navigate to Alerts → Events to see all fired alert events. Analysts can review and acknowledge alerts.

Alert Event States

StateMeaningAnalyst Action
OpenAlert has fired and has not been reviewedInvestigate and acknowledge or resolve
AcknowledgedAlert has been noted by an analyst — investigation in progressResolve when condition is cleared
ResolvedAlert condition has been cleared or investigated to completionNo action needed
Click an alert event to see the detail panel, which shows the triggering rule, the time window that fired it, and a link to search the Log Explorer for the relevant events.

Common Investigation Workflows

Investigating a Security Event

1. Open the Log Explorer and set the time range to the suspected incident window.
2. Filter by Severity: error + critical + emergency.
3. Add a Host filter if you know the affected device.
4. Use Keyword Search to narrow by event type (e.g. "denied", "failed", "authentication").
5. Expand relevant rows to view all structured fields and the raw syslog message.
6. Export the filtered results as CSV or JSON for your incident report.

Checking a Specific Device

Set Host to the device name or IP, select a 24h window, and leave other filters open. Review the volume timeseries at the top of the results for anomalous spikes, then drill down into the specific time bucket of interest.

Compliance Evidence Collection

Filter by Facility: auth and Program: sshd (or your authentication daemon) for a defined time range. Export as CSV with all fields. The raw_message field provides the original unmodified syslog line for audit-trail purposes.

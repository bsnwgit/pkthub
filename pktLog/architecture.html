Ingest Pipeline

How a syslog message becomes data.

Every syslog event follows a deterministic pipeline from raw bytes to a structured ClickHouse record in under 100ms.

01

Receive — UDP or TCP, port 8761

pktLog binds dual sockets on the ingest port. UDP datagrams are received in a single read loop; TCP connections accept a stream of newline-delimited messages. Both paths feed the same parser queue.

02

Parse — RFC 3164 and RFC 5424

The parser auto-detects format by inspecting the first byte. RFC 5424 messages begin with a PRI+version header; RFC 3164 messages use the legacy BSD format. Both are decoded into a common intermediate structure: priority, facility, severity, timestamp, hostname, app_name, pid, and message.

03

Normalize — Enrich and validate

The normalizer maps numeric priority to human-readable severity and facility strings, fills in missing fields with defaults, and applies site/group/collector enrichment based on the sending IP address and the collector registry. A received_at server timestamp is always added.

04

Batch — In-memory buffer with configurable flush interval

Normalized records accumulate in an in-memory batch buffer. When the flush interval elapses (default: 5 seconds) or the maximum batch size is reached, the buffer is flushed to ClickHouse as a single bulk INSERT, minimizing round-trip overhead.

05

Write — ClickHouse with journal fallback

The batch is written to pktlog.syslog_events. If ClickHouse is unreachable, the batch is written to the local ingest journal on disk. The journal replays automatically when ClickHouse becomes available again — no events are lost during brief storage outages.

Storage Design

ClickHouse schema — syslog_events

The core event table stores one row per syslog message. MergeTree engine provides fast range scans and efficient TTL-based retention.

CREATE TABLE pktlog.syslog_events (
    received_at    DateTime,           -- server-side ingest timestamp
    event_time     DateTime,           -- parsed message timestamp
    host           String,             -- source hostname / IP
    severity       LowCardinality(String), -- emergency..debug
    facility       LowCardinality(String), -- kern, auth, daemon...
    priority       UInt8,              -- raw PRI value (0-191)
    program        String,             -- app_name / process name
    pid            String,             -- process ID (string for compat)
    message        String,             -- parsed message body
    raw_message    String,             -- original unmodified syslog line
    collector_ip   String,             -- IP of the sending collector
    collector_name String,             -- name from collector registry
    site           LowCardinality(String), -- site label from registry
    group_name     LowCardinality(String), -- org/group from registry
    msg_id         String,             -- RFC 5424 MSGID (if present)
    structured_data String,            -- RFC 5424 SD element (if present)
    ingest_id      UUID DEFAULT generateUUIDv4() -- unique event ID
) ENGINE = MergeTree()
  PARTITION BY toYYYYMM(received_at)
  ORDER BY (received_at, host, severity)
  TTL received_at + INTERVAL 90 DAY;

Why ClickHouse?

Columnar storage means querying severity across 100M rows reads only that column — not the full row. Aggregation queries like GROUP BY host, severity execute 10–100× faster than row-based databases at scale.

Retention Policy

The MergeTree TTL clause automatically purges events older than the configured retention window (default 90 days). Retention is adjustable in Settings → Ingest without requiring schema changes.

SQLite — App Config

Non-event data lives in SQLite: user accounts, hashed passwords, JWT config, alert rules, alert events, collector registry, and all application settings. Small and transactional — exactly the right tool.

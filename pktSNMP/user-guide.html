Operator Guide

Using pktSNMP

Complete reference for network operators and analysts using the pktSNMP monitoring platform.

Introduction

pktSNMP is a real-time SNMP monitoring platform that collects telemetry from routers, switches, firewalls, and other network devices and displays it in an interactive dashboard.

👁
Monitor Device Health
Live up/down status for every device, organized by site and group.
📈
Analyze Traffic Metrics
Per-interface traffic rates, error counts, and operational status over time.
🔔
Respond to Alerts
Acknowledge and track alert events when devices go down or thresholds are crossed.
🤖
Query with AI
Ask plain-English questions about your network — get answers backed by live data.

Logging In

Navigate to your pktSNMP server URL in a web browser to reach the login page.

1
Enter credentials

Use the username and password your administrator provided, or click "Sign in with SSO" for single sign-on.

2
Dashboard loads

After successful login you land on the main Dashboard. Your session stays active for 7 days via a secure refresh token.

3
Change your password

If given a default password, go to Settings → Users and update it immediately.

ℹ️

SSO users: If your organization uses a SAML identity provider, click "Sign in with SSO." Your role is assigned by your IT admin in the identity provider — no action required on your part.

Dashboard

The Dashboard is your home base — a real-time summary of your entire network in one view.

Environment Card

The left panel shows the Environment Tree: a hierarchical list of all devices grouped by Org → Group → Site → Device. Status dots roll up from device to site to group — one red device instantly surfaces at every level above it.

Collector Activity

Small bar chart sparklines beneath each collector name show recent ingest activity. A flat sparkline means that collector hasn't sent data recently — contact your administrator.

Alert Badge

The navigation sidebar shows a live count of open, unacknowledged alerts, updated every 30 seconds.

Environment Tree

The Environment Tree gives you an at-a-glance picture of your entire network topology. Each node has a colored status dot:

Red (pulsing)

At least one device beneath this node is down or unreachable.

Yellow (pulsing)

At least one device has an active alert but is not fully down.

Green

All devices beneath this node are up and reporting normally.

Gray

No enabled devices, or status is unknown (no recent data).

Clicking a Device

Click any device in the tree to open the Device Metrics Panel — a slide-in panel showing traffic sparklines, interface status, and quick links to the full Metrics page and alert rule creation.

Hierarchy Levels

The tree uses four levels: Org (top level, e.g., your company) → Group (a business unit or region) → Site (a physical or logical location) → Device (individual managed device).

Devices Page

The Devices page lists every network device registered in pktSNMP. Use it to find a specific device, check its current status, or manage device records (Admin / Analyst roles).

Device Fields

FieldDescription
NameDisplay name shown in the tree and metrics pages
Device TypeRouter / Switch / Firewall / Server / Wireless / UPS / Other
StatusCurrent up/down/unknown status from the most recent poll or trap
Last SeenTimestamp of the most recent data received from this device
CollectorWhich collector is responsible for polling this device
HA RoleStandalone / Active / Standby — for high-availability device pairs

CSV Export / Import

Use the Export CSV button to download all device records. Analysts and admins can use Import CSV to bulk-create or update devices. New rows (unrecognized name + IP) are created; existing rows are updated by name match.

Metrics & Charts

The Metrics page provides full time-series visualization for any device. Access it by clicking View Full Metrics → in the Device Metrics Panel, or by navigating to Metrics in the sidebar and selecting a device.

Available Charts

Traffic (bps)
Inbound and outbound bytes per second per interface. Identifies bandwidth saturation.
Packets/sec
Unicast packet rate per interface. Useful for traffic pattern analysis.
Errors & Discards
Input/output error and discard counts per interface over the selected time range.
Interface Speed
Negotiated speed per interface. Speed changes trigger alerts when configured.

Time Range Selection

Use the time picker in the top right of the Metrics page to select a preset range (1h, 6h, 24h, 7d) or enter a custom range. The URL updates to reflect your selection, so you can share a link to a specific view.

Alert & Trap Overlays

Alert events and SNMP traps are shown as vertical markers on the charts, so you can correlate spikes in traffic or errors with specific incidents.

CSV Export

Click Export CSV on the Metrics page to download the raw time-series data for the selected device and time range. Useful for offline analysis or reporting.

💡

Tip: Bookmark a metrics URL with your preferred device and time range so you can return to the same view quickly.

Alerts

The Alerts page shows all alert events — both open and resolved — generated by the alert engine. The engine evaluates all enabled rules every 60 seconds.

Built-in Rule Types

  • Interface down
  • Interface flapping
  • Metric threshold
  • Metric spike
  • Error rate
  • Discard rate
  • High error ratio
  • Bandwidth utilization
  • Speed change
  • Collector gap
  • Device unreachable
  • Trap received

Alert States

Open / Firing

Condition is currently active. Device may be down or threshold exceeded.

Resolved

Condition cleared automatically — device recovered or metric returned to normal.

Acknowledged

An analyst or admin has acknowledged the event. Still open but noted.

Acknowledging Alerts

Analysts and Admins can acknowledge open alerts by clicking the Acknowledge button on the alert row. This marks the alert as seen but does not resolve it — the engine will auto-resolve it when the condition clears.

Notification Channels

Alerts fire to configured channels: in-app badge, email, Slack, PagerDuty, or custom webhook. Contact your administrator to set up or modify notification channels in Settings → Alerts.

Collectors

The Collectors page shows all registered data collectors — both the built-in local collector and any remote otelcol instances.

Collector Status

Each collector card shows a status indicator and a sparkline of recent poll activity (ingest events per time bucket). If a collector shows "unknown" status, it hasn't pushed data recently — this may indicate a network issue or a misconfigured remote collector.

Local vs. Remote Collectors

TypeHow it worksWhere it runs
LocalBuilt-in pysnmp engine polls devices assigned to collector_id=1 and listens on UDP 162 for trapsIn-process on the pktSNMP server
RemoteAn otelcol-contrib instance polls devices at a remote site and sends data via OTLP HTTPOn a remote host at each site

AI Assistant

The AI Assistant is accessible from the sidebar. It lets you ask natural-language questions about your network and get answers drawn directly from your live telemetry data.

Example Questions

"Which devices had interface errors in the last 2 hours?"
"Show me bandwidth utilization for Site A switches over the last 24 hours."
"Are there any devices that haven't been seen in the last 30 minutes?"
"What was the peak traffic rate on the core router yesterday?"

The AI assistant uses your actual metric data to answer — it is not a general-purpose chatbot. Complex or ambiguous questions may require more specific phrasing.

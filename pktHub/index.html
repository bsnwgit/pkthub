Platform Overview

Three integrated platform areas

pktHub provides a single control plane across all pktAPP applications — from registration and token management to unified display and noc publishing.

⚙

App Registry

Register pktAPP applications by pasting their suite token. Monitor health status, view registration details, and deregister apps — all from Settings → App Registry.

⬡

Managed App Viewer

Access any registered pktAPP through pktHub's reverse-proxy shell. A 44px persistent top bar stays in view while the full pktAPP UI fills the rest of the viewport.

⊞

NOC Builder

Drag-and-drop widget composer sourced from all registered pktAPPs. Publish displays to wall monitors with signed, revocable URL tokens — no login required on the display end.

⊡

Context Viewer

Full-screen dedicated viewer for any registered pktAPP at /context. App-selector dropdown, no pktHub sidebar — ideal for a focused secondary monitor or deep-dive session.

🔒

Unified Auth

pktHub becomes the sole authentication provider after registration. JWT tokens issued by pktHub are validated by all managed pktAPPs. Optional Okta SAML 2.0 SSO supported.

📋

Audit & Settings

Platform-wide audit logging, user management, notification routing (Slack, Email, PagerDuty, Webhook, TraceCat), and tabbed settings following the standard pktAPP admin pattern.

🛡

Break-Glass Recovery

Every pktAPP ships with an --emergency-unlock CLI flag. Triggers full deregistration, restores direct access, and logs the event in pktHub automatically.

Registration Workflow

Observe first, manage when ready

pktHub never seizes control immediately. Every pktAPP transitions through observe mode so operators can validate before enabling the full token lockout.

1
Register
Operator copies suite token from pktApp Settings → Integrations, then pastes it into pktHub Settings → App Registry. pktHub validates via /api/health and stores it.
2
Observe Mode
pktHub monitors and proxies the app, but direct pktAPP access still works normally. Local pktAPP users remain active.
3
Validate
Operator confirms proxy routing, role mapping, noc widgets, and health polling are working as expected.
4
Managed Mode
Flip the toggle. pktAPP now requires X-Suite-Token on every request. Direct web access returns 403. Local users dormanted.
5
Deregister
Full clean break — suite-token removed, direct access restored, local users un-dormanted, app removed from registry.

NOC Builder

Wall displays, no browser login

Build, compose, and publish live network dashboards to wall monitors. Signed display tokens mean the screen loads once and refreshes forever without credential prompts.

⊞

Widget Library — 24 widgets

pktHub polls each app's /api/widgets/manifest every 60 seconds. New widgets appear automatically. Current catalog: pktFlow (9), pktLog (6), pktSNMP (6), pktPCAP (3).

⊡

1920×1080 Canvas

Drag-and-drop widget placement on a full-HD canvas. Zoom controls (25%–200%) let you edit detail without scrolling. Widget borders are colored in their source app's accent color.

↔

Scale-to-Fit Display

The published display page scales the 1920×1080 canvas to fill any screen resolution without cropping — like a presentation. Works on any wall monitor, TV, or kiosk out of the box.

↻

Slide Rotation

Static live-refresh or rotating slide mode with configurable dwell time. Iframes remount on every slide change for guaranteed fresh data — no stale caches on wall monitors.

🔗

Signed Display Tokens

Published NOC displays get a URL-based signed token. No login on the display device. Revoke from pktHub instantly. All widget data proxied through /proxy-display/{token}/….

Architecture

How pktHub connects to pktAPPs

Click the diagram to enlarge.

  • Reverse Proxy Shell + Context ViewerpktHub proxies all traffic to managed pktAPPs. A 44px top bar persists; the pktAPP UI fills the rest of the viewport. Context Viewer (/context) provides a full-screen single-app focus mode with no sidebar.
  • Widget Manifest PollingpktHub polls each app's /api/widgets/manifest every 60 s. 24 widgets available across 4 apps — pktFlow (9), pktLog (6), pktSNMP (6), pktPCAP (3). New widgets appear in the NOC Builder automatically.
  • API VersioningAll pktHub↔pktAPP API calls carry X-Suite-Version: 1. pktAPPs advertise supported versions at registration; pktHub negotiates the highest mutual version.
  • Audit Log IsolationPlatform audit logs are stored in pktHub's own SQLite DB — never forwarded to pktLog. This prevents circular dependency during incidents.
  • SPOF MitigationpktHub runs as a hardened systemd service with auto-restart. Health endpoint stays live even when the main app is degraded. Break-glass CLI available on every pktAPP.

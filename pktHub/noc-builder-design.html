NOC Builder
Design Plan

Full widget-based wall display composer — auto-discovery via 60-second manifest polling, 1920×1080 free-form drag canvas with zoom controls, scale-to-fit display, and credential-free public display. Core features implemented.

Foundation

What already exists

More backend infrastructure is in place than the UI suggests. The NOC builder expansion builds on a solid foundation.

✓

Backend CRUD

Full noc create / read / update / delete in noc.py. Publish/unpublish with signed display token. layout stored as JSON blob.

✓

Pydantic Models

NOCWidget and NOCSlide are already defined in models.py with id, app_id, widget_type, title, x, y, w, h, config. Layout schema just needs to be used consistently.

✓

widget_manifest field

AppOut already carries widget_manifest: List[Any] = []. Once pktApps expose the manifest endpoint, pktHub stores and surfaces it automatically.

✓

Public Display Endpoint

GET /api/noc/display/:token requires no authentication — token-only access. NOCDisplayPage just needs to avoid adding auth headers.

✓

NOCBuilderPage

List / create / delete noc, publish/unpublish toggle, copy display link. Missing: the widget editor that lets users actually add widgets to a noc.

✓

Display Bug Fixed

NOCDisplayPage now reads noc.layout (not noc.slides). Scale-to-fit rendering implemented — the 1920×1080 canvas scales via transform:scale() to fill any screen. Iframes remount on every slide rotation via key prop.

Design Decisions

Four principles driving the build

These decisions were made to keep the hub dumb and the apps smart — minimizing future maintenance.

⟳

Auto-Discovery via pktApp

Each pktApp exposes GET /api/widgets/manifest. pktHub reads it during health checks and stores it in the app registry. When a pktApp developer adds a new widget, pktHub picks it up on the next health cycle — zero hub changes required.

⊹

Free-Form Drag Arrangement

No grid snapping. Widgets are placed at absolute pixel coordinates (x, y, w, h) on a 1920×1080 reference canvas. Zoom controls (25%–200%) let you edit at any scale — coordinates are divided by zoom factor so stored positions are always in 1920×1080 space. The display page renders at the same coordinates, scaled to fit the target screen.

⊞

Display Behavior Set in Builder

Display mode (Static live-refresh / Rotating slides / Manual advance), per-slide dwell time, and future display options are all configured inside the editor — not at noc creation time. The creation form only sets name and description.

🔗

No Credentials for Display

The public display URL /display/:token requires no login. Admin/Analyst builds and publishes; the signed token is all that's needed to display anywhere — wall TVs, digital signage, remote screens. Token revoked instantly on unpublish.

Auto-Discovery

Hub reads, apps declare

The widget library in the builder is driven entirely by what pktApps report via their manifest endpoint.

1
pktApp adds widget
Developer adds a new widget view route and one entry to the manifest response. No hub changes.
2
Health check fires
pktHub polls /api/widgets/manifest on each registered app every 60 seconds. 24 widgets currently registered across 4 apps.
3
Manifest stored
Hub updates widget_manifest on the app registry row. The new widget is now known to pktHub.
4
Builder shows it
The widget library panel reads widget_manifest from GET /api/apps and displays the new widget automatically.
5
Display renders it
NOCDisplayPage loads widgets as iframes. For authenticated sessions: /proxy/{app_id}{view_path}. For public display tokens: /proxy-display/{token}/{app_id}{view_path}. The pktApp serves its own widget HTML via FastAPI routes.
Data Schema

Manifest + Layout JSON

Two JSON contracts define the entire system. pktApps own the manifest; pktHub owns the layout.

pktApp Widget Manifest

Served by each pktApp at GET /api/widgets/manifest

[
  {
    "id": "flow_map",                   // stable ID
    "title": "Network Flow Map",
    "description": "Live packet flow",
    "view_path": "/widgets/flow_map",   // iframe src
    "default_w": 600,
    "default_h": 400,
    "min_w": 300,
    "min_h": 200
  }
]

Each widget view at view_path is a minimal fullscreen HTML page that auto-refreshes its own data via setTimeout(reload, 30000). For FastAPI apps, view_path includes the /api prefix (e.g. /api/widgets/flow_map). pktHub proxies it at /proxy/{app_id}{view_path}. The hub has no knowledge of widget internals.

NOC Layout JSON

Stored in noc_layouts.layout (SQLite JSON blob)

[ // array of slides
  {
    "id": "slide-1",
    "title": "Main View",
    "dwell_seconds": 30,
    "widgets": [
      {
        "id": "w-abc",
        "app_id": 18, // registered app
        "widget_id": "flow_map",
        "view_path": "/widgets/flow_map",
        "title": "Network Flow",
        "x": 20, "y": 20,
        "w": 640, "h": 420 // px
      }
    ]
  }
]

view_path is cached from the manifest at placement time so layouts remain valid even if a widget is later removed from the manifest.

Editor UI

NOCEditorPage — /noc/:id/edit

A new page linked from each noc card's Edit button. Three-panel layout: widget library, free canvas, widget config.

≡

Left — Widget Library

Lists all available widgets grouped by pktApp. Each entry shows the widget title and description. Dragging from this panel onto the canvas places the widget. Widgets from offline apps are grayed out. Library updates automatically as new widgets are registered.

⊹

Center — Free Canvas

Dot-grid background on a 1920×1080 reference canvas. Zoom controls (25%–200%) in the top bar scale the canvas via transform:scale(zoom) — coordinate math always divides by zoom factor so stored positions stay in 1920×1080 space. Widgets absolutely positioned, freely draggable, resizable from corner handle. Click to select (highlighted border). Drop zone highlights on drag-over.

⚙

Right — Config + Display

Shows config for the selected widget: editable title, read-only source app and widget type, x/y/w/h numeric inputs. Also shows slide-level display mode options: Static, Rotating (with dwell seconds), or Manual advance. Remove widget button at bottom.

Top Bar Controls

← Back to NOC Displays
Returns to NOCBuilderPage list. Prompts to save if unsaved changes exist.
Slide Tabs
For rotating mode: each slide is a separate canvas. Tabs added with + Slide button. Per-slide dwell configured in right panel.
Display Mode Selector
Pill control in top bar: Static / Rotating / Manual. Changes apply to the whole noc. For rotating, dwell defaults to the noc-level dwell_seconds but can be overridden per slide.
Zoom Controls
25% / 50% / 75% / 100% / 150% / 200% presets in the top bar. Canvas inner div scales via transform:scale(zoom); outer container stays at 1920×1080 layout footprint. Coordinate math divides by zoom when placing/moving widgets.
Save Layout
Calls PATCH /api/noc/:id with the full layout JSON. No auto-save — explicit save required. Publish/unpublish remains on the NOCBuilderPage card.
Access Control

Who can build, who can display

Builder access follows the pktHub role model. Display is intentionally public.

RoleCreate NOCEdit LayoutPublish / UnpublishCopy Display URLView Display
Admin✓✓✓✓✓ (no login)
Analyst✓✓✓✓✓ (no login)
Viewer✗✗✗✗✓ (no login)
Anonymous / TV / Signage✗✗✗✗✓ token only
Display URL is fully public: /display/:token — no session, no cookie, no auth header. The token is generated on publish and invalidated on unpublish. Safe for wall TVs, digital signage players, or any browser that has the URL. NOCDisplayPage must never attach an Authorization header when fetching the display endpoint.

Build order

Sequenced so each step is independently testable before the next begins.

Bug Fix

Widget Manifest Endpoints ✓
GET /api/widgets/manifest implemented on all 4 pktApps. pktHub polls every 60 s, stores in widget_manifest. 24 widgets total: pktFlow (9), pktLog (6), pktSNMP (6), pktPCAP (3).
3
Widget View Routes ✓
All 24 widget views implemented across 4 apps. Each returns a fullscreen HTML page at GET /api/widgets/{type} with setTimeout(reload, 30000). pktHub proxies via /proxy/{app_id}/api/widgets/{type}.
4
NOCEditorPage
New NOCEditorPage.tsx at /noc/:id/edit. Widget library (left) + free-form drag canvas (center) + config/display-mode panel (right). Saves via PATCH.
5
Display Page Polish ✓
Scale-to-fit: scale = Math.min(vw/1920, vh/1080) applied as transform:scale(). Slide rotation with key={currentSlide}-{w.id} forces iframe remount on each slide change — guarantees fresh data on wall monitors.
F
Future: Config Schema
Widget manifest entries include config_schema (JSON Schema). Editor right panel auto-generates widget-specific config form. No hub changes needed per widget.

Network & Security
Analyst Guide

Learn how to upload packet captures, connect live feed sources, interact with the AI analysis engine, and extract findings from the multi-tab dashboard.

Logging In

pktPCAP is a secure, browser-based application. Open your organization's pktPCAP URL in any modern browser. You will be presented with the login screen.

Local Authentication

Enter your assigned username and password, then click Sign In. If you have not yet been issued credentials, contact your platform administrator.

Single Sign-On (SSO)

If your organization has configured SAML SSO, click Sign in with SSO on the login page. You will be redirected to your organization's identity provider. After completing authentication there, you will be returned to pktPCAP automatically. SSO accounts are provisioned on first login — no pre-registration is required.

ℹ️

Your username appears in the sidebar footer after login. Your assigned role (Admin / Analyst / Viewer) determines which features are available to you.

The Interface

The pktPCAP interface is divided into four primary areas:

  • Left Sidebar: Navigation between sections — Dashboard, Live Feeds, and Settings (Admin only).
  • Upload / Landing Zone: The central drop area when no capture is loaded. Drag files here or browse for them.
  • Data Panel: The tabbed analysis pane that appears after a capture is processed. Contains all protocol, stream, endpoint, and summary views.
  • AI Chat Panel: The right-side conversation panel for querying the AI analysis engine about the loaded capture.
💡

Click ↩ New Analysis in the top bar at any time to clear the current session and start fresh with a new file or feed.

Uploading PCAP Files

Uploading a capture file is the primary way to begin an analysis session. pktPCAP supports standard Wireshark and tcpdump capture formats.

Step 1

Select Your File(s)

Drag one or more .pcap, .pcapng, or .cap files directly onto the upload drop zone, or click the zone to open a file picker. Multiple files can be selected at once.

Step 2

Multi-File Merge

When multiple files are uploaded together, pktPCAP automatically merges and correlates them into a single unified session. This is useful for analyzing captures taken from multiple taps or time windows simultaneously.

Step 3

Start Analysis

Click Analyze. The server parses the capture, decodes all layers, reconstructs streams, and resolves DNS. The data panel and AI panel load when processing completes.

⚠️

Very large captures (over a few hundred MB) may take additional time to process. If your capture is from a long session, consider filtering it with Wireshark or tshark before uploading to focus on the relevant timeframe.

Live Feed Capture

Live feeds allow you to stream packet data from a remote host directly into pktPCAP in real time — no intermediate file save required. Navigate to Live Feeds in the sidebar to access this feature.

Active Sessions

Any currently streaming feed sessions will appear at the top of the Live Feeds page. Click a session to load it into the dashboard.

Connecting a Remote Host

To start a new live capture from a remote host, fill in the connection form:

  • Feed Name: A label for this session (e.g., core-switch-uplink).
  • Interface: The network interface to capture on (e.g., eth0, ens3).
  • Filter: An optional BPF capture filter to limit what is recorded (e.g., not port 22 to exclude SSH management traffic).

Using tshark (CLI)

After configuring the options above, pktPCAP generates the exact tshark command to run on your remote host. Copy it with the Copy Command button, then paste and execute it in an SSH session on the target machine. The feed will begin appearing in pktPCAP within seconds.

# Example generated tshark command (your actual command is generated by the UI)
tshark -i eth0 -f "not port 22" -w - | curl -s -X POST \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/octet-stream" \
  --data-binary @- \
  https://<your-server>/api/feed/<feed-name>

Using Wireshark (GUI)

If you prefer a graphical Wireshark workflow, select the Wireshark tab in the Live Feeds section. Configure Wireshark to use pktPCAP as its remote capture destination — Wireshark will SSH into the pktPCAP server and the stream is simultaneously displayed in Wireshark and recorded in pktPCAP.

ℹ️

Each live feed has a unique authentication token generated by pktPCAP. This token is embedded in the generated command — treat it like a password and do not share it outside the capture workflow.

Running an Analysis

Whether you loaded a file or connected a live feed, the analysis workflow is the same. After data is loaded, the platform automatically populates all tabs in the data panel.

What Happens During Analysis

  • All packets are decoded layer by layer (Ethernet → IP → TCP/UDP → Application).
  • TCP and UDP streams are reconstructed and indexed for browsing.
  • Protocol distribution is computed across the full capture.
  • DNS queries and responses are correlated to IP addresses.
  • Endpoint pairs, byte counts, and packet counts are tabulated.
  • An AI-generated summary is produced automatically and appears in the chat panel.

Analysis Tab Reference

The data panel on the right side of the dashboard contains multiple scrollable tabs. Each tab surfaces a different analytical view of the loaded capture.

📋
Summary
Top-level capture statistics: total packets, total bytes, capture duration, start/end timestamps, and a count breakdown by top protocols. The first tab loaded after any analysis.
🔬
Protocols
Full hierarchical protocol breakdown — Ethernet, IP, TCP, UDP, HTTP, DNS, TLS, ICMP, and more — with packet counts and byte totals for each. Drill into any protocol row to see individual frames.
🔁
Streams
Reconstructed TCP and UDP conversations. Click any stream to load the full payload sequence — useful for inspecting HTTP request/response cycles, DNS lookups, or unencrypted application traffic.
🌐
Endpoints
All communicating IP endpoints with their total packet and byte counts, resolved hostnames, and inbound/outbound breakdown. Sort by any column to surface top talkers or unusual peers.
💬
Conversations
Bi-directional traffic pairs (source ↔ destination) across all transport layer protocols. Useful for identifying all communication between two specific endpoints.
📦
Packets
Frame-level view with timestamps, source/destination addresses, protocol, length, and info columns. Click any frame to see the full decoded field breakdown.
🌍
DNS
All DNS queries and responses captured in the session. Shows query names, record types, resolved addresses, and response codes. Quickly spot unusual external resolutions or failed lookups.
🔒
TLS / HTTP
Dedicated views for TLS handshakes (certificate SNI, cipher suites, versions) and HTTP transactions (methods, URLs, status codes, user agents) where visible in the capture.

AI-Assisted Analysis

The chat panel on the right side of the dashboard connects to an AI engine (OpenAI or Anthropic Claude, as configured by your administrator). After an analysis runs, the AI automatically generates an opening summary of the capture. You can then continue the conversation with natural-language questions.

What the AI Can Help With

  • Summarizing traffic patterns and anomalies in plain language
  • Identifying unusual port usage, connection failures, or protocol mismatches
  • Explaining what a specific protocol exchange means
  • Correlating events across streams (e.g., "what happened before this DNS query resolved?")
  • Answering questions about endpoint behavior or data volumes
  • Flagging potential indicators of compromise from traffic patterns

Example Prompts

EXAMPLE PROMPT
"What are the top 5 external IPs this host is communicating with?"
EXAMPLE PROMPT
"Are there any failed authentication attempts or reset connections in this capture?"
EXAMPLE PROMPT
"Summarize the DNS queries — are there any unusual domains being resolved?"
EXAMPLE PROMPT
"Which TLS versions are in use? Are any sessions negotiating outdated cipher suites?"
ℹ️

Raw packet payload data is not sent to the AI provider. Only structured metadata, protocol summaries, and your typed questions are transmitted. All raw packet bytes remain on your organization's server.

Exporting Results

Analysis findings can be exported from the dashboard for use in incident tickets, reports, or knowledge base articles.

Available Exports

  • Protocol Summary: Export the protocol breakdown as a structured table.
  • Endpoint List: CSV-compatible list of all communicating endpoints with traffic volumes.
  • AI Analysis Text: Copy the full AI conversation thread, including the auto-generated summary, for pasting into tickets or documents.
  • Stream Data: Individual stream payloads can be copied directly from the Streams tab.

Dashboard Screenshots

The Screenshot function captures the current state of the full dashboard — including the data panel and AI chat — and saves it as an image file on the server. Administrators can configure the save path in Settings. This feature is useful for visual record-keeping or including UI state in documentation.

💡

The screenshot capture feature requires the server to have screenshot tooling available (e.g., a headless browser or OS-level capture tool). If it's not responding, check with your administrator that the server-side dependency is installed.

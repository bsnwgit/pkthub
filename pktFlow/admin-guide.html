IT ADMIN / OPERATOR GUIDE

pktFlow Admin Guide

This guide covers deploying, configuring, and operating pktFlow — including server setup, collector pipeline configuration, ClickHouse management, user administration, and troubleshooting procedures.

📋 System Requirements

Network Prerequisites

  • Routers/switches must support NetFlow v9 export
  • NetFlow export target: collector node IP, UDP port 2055
  • Collector node must have HTTP reach to the pktFlow server's API port
  • Browser access to the pktFlow server's web port for dashboard users

📦 Installation

1. Clone the Repository

git clone <repository-url> /opt/pktflow
cd /opt/pktflow

2. Create Python Virtual Environment

python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

3. Install ClickHouse

# Add ClickHouse repo (Amazon Linux / RHEL)
curl https://packages.clickhouse.com/rpm/clickhouse.repo \
  -o /etc/yum.repos.d/clickhouse.repo
yum install -y clickhouse-server clickhouse-client

# Start and enable
systemctl enable --now clickhouse-server

4. Configure pktFlow

Copy the example config and edit it for your environment:

cp config.example.yaml config.yaml
nano config.yaml

Key fields to set:

FieldDescription
server.portPort the web server listens on
server.hostBind address (use 0.0.0.0 for all interfaces)
clickhouse.hostClickHouse host (usually localhost)
clickhouse.databaseClickHouse database name for pktFlow
auth.secret_keyJWT signing key — change from the default immediately
ingest.tokenBearer token required by collectors to authenticate ingest POSTs
🚨 Security: Always change auth.secret_key and ingest.token from the defaults before any production use. Use strong random values (32+ characters).

5. Build the Frontend

# On the server, in a Linux shell
cd /opt/pktflow/frontend
npm install
npm run build

6. Install and Start the Service

cp pktflow.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now pktflow
systemctl status pktflow

⚙️ Configuration Reference

The config.yaml file controls all pktFlow behavior. Below is the full structure with descriptions.

server:
  host: "0.0.0.0"        # Bind address
  port: 8080             # Web + API port
  workers: 1             # Uvicorn worker processes

clickhouse:
  host: "localhost"      # ClickHouse server hostname
  port: 9000             # ClickHouse native protocol port
  database: "pktflow"    # Database name
  user: "default"        # ClickHouse user
  password: ""           # ClickHouse password (blank if none)

auth:
  secret_key: "CHANGE_ME_STRONG_RANDOM_32CHARS"
  algorithm: "HS256"
  token_expire_minutes: 480  # 8 hours

ingest:
  token: "CHANGE_ME_INGEST_TOKEN"
  buffer_size: 1000      # Flush to ClickHouse after N records
  flush_interval: 5      # Or every N seconds, whichever comes first

logging:
  level: "INFO"          # DEBUG | INFO | WARNING | ERROR
  access_log: true       # Set false to suppress HTTP access log

📡 Collector Setup

Each collector node runs two components in a pipeline: goflow2 (decodes binary NetFlow from the network) and Vector (transforms, enriches, and ships the data to pktFlow).

Install goflow2

# Download latest release binary
mkdir -p /opt/goflow2
curl -L https://github.com/netsampler/goflow2/releases/latest/download/goflow2-linux-amd64 \
  -o /opt/goflow2/goflow2
chmod +x /opt/goflow2/goflow2

Install Vector

curl --proto '=https' --tlsv1.2 -sSf \
  https://sh.vector.dev | bash -s -- -y
# or via package manager for your distro

Vector Configuration

Create /etc/vector/vector.toml (or your chosen config path):

[sources.netflow_in]
type = "stdin"            # goflow2 pipes stdout directly to vector

[transforms.parse_flow]
type = "remap"
inputs = ["netflow_in"]
source = '''
  . = parse_json!(string!(.message))
'''

[transforms.enrich]
type = "remap"
inputs = ["parse_flow"]
source = '''
  .site = if includes(["SAMPLER_IP_1", "SAMPLER_IP_2"], .sampler_address) {
    "site-a"
  } else if includes(["SAMPLER_IP_3"], .sampler_address) {
    "site-b"
  } else {
    "unknown"
  }
'''

[sinks.pktflow]
type = "http"
inputs = ["enrich"]
uri = "http://<PKTFLOW_SERVER>:<PORT>/api/ingest/flows"
method = "post"
encoding.codec = "json"
framing.method = "newline_delimited"
batch.max_events = 500
batch.timeout_secs = 2
[sinks.pktflow.auth]
strategy = "bearer"
token = "<YOUR_INGEST_TOKEN>"

Systemd Service (Collector)

[Unit]
Description=pktFlow NetFlow Collector (goflow2 + Vector)
After=network-online.target

[Service]
Type=simple
ExecStart=/bin/bash -c "/opt/goflow2/goflow2 \
  -format json \
  -listen netflow://0.0.0.0:2055 | \
  vector --config /etc/vector/vector.toml"
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
ℹ️ On some systemd configurations, stdin is set to /dev/null for services, which breaks the pipe approach. If goflow2 cannot write to stdout/stdin, use Vector's exec source type instead: set type = "exec" and set command to the goflow2 binary with its arguments.

🔄 Ingest Pipeline Details

Understanding how data flows through the pipeline helps you diagnose issues when flows stop appearing in the dashboard.

Field Transformation

Vector normalizes goflow2's output before sending to pktFlow. Key transformations:

Raw goflow2 FieldAfter Vector TransformNotes
SrcAddrsrc_addrLowercased snake_case
Proto (int)proto (string)"TCP", "UDP", "ICMP"
NextHop: "0.0.0.0"next_hop: ""Empty string, not 0.0.0.0
(none)siteAdded by Vector enrich transform
(none)sampler_addressSource router IP

Ingest Buffer Behavior

pktFlow holds incoming records in memory and flushes them to ClickHouse either when the buffer reaches buffer_size records or when flush_interval seconds have elapsed — whichever comes first. This batching dramatically improves ClickHouse write throughput.

✅ Verify Ingest is Working

After deploying, confirm end-to-end data flow with these checks:

1

Check Collector Service

On the collector node: systemctl status <collector-service-name>. It should show active (running).

2

Check pktFlow Service

On the application server: systemctl status pktflow. Should show active (running).

3

Query the Ingest Stats Endpoint

Run: curl http://localhost:<PORT>/api/ingest/stats. The total_received counter should be non-zero and incrementing.

4

Check the Dashboard

Open the browser dashboard. If the traffic chart shows data, the full pipeline is working.

⚠️ If total_received is 0 despite Vector sending data (visible in pktFlow's access log), the normalizer is silently dropping records. Check that Vector is sending snake_case fields, and that proto is a string not an integer.

🛠️ Service Management

Common Commands

# Check status
systemctl status pktflow

# Restart after config or code changes
systemctl restart pktflow

# View live logs
journalctl -u pktflow -f

# View last 100 lines of logs
journalctl -u pktflow -n 100
ℹ️ After a pktFlow restart, Vector's exponential backoff may cause a brief delay (up to a few seconds) before flows resume. A pktFlow restart (connection reset) triggers an immediate reconnect from Vector, so in practice the gap is usually negligible.

Updating pktFlow

1

Pull latest code

git pull in the pktFlow directory.

2

Update Python deps (if requirements changed)

source venv/bin/activate && pip install -r requirements.txt

3

Rebuild frontend (if frontend changed)

Run the frontend deploy process: sync source to server, npm install, npm run build, copy dist.

4

Restart the service

systemctl restart pktflow

🗄️ ClickHouse Administration

pktFlow uses ClickHouse as its primary data store. Familiarity with basic ClickHouse operations is helpful for administration.

Connect to ClickHouse

clickhouse-client --host localhost --database pktflow

Check Table Size

SELECT
  table,
  formatReadableSize(sum(bytes)) AS size,
  sum(rows) AS rows
FROM system.parts
WHERE database = 'pktflow'
GROUP BY table;

Check Recent Ingestion

SELECT count(), max(time_received_ns) FROM flows
WHERE time_received_ns > now() - INTERVAL 5 MINUTE;

Data Retention

pktFlow does not have a built-in data retention job. To limit storage growth, configure a TTL on the flows table:

-- Keep data for 90 days
ALTER TABLE flows MODIFY TTL
  toDateTime(time_received_ns / 1000000000) + INTERVAL 90 DAY;
💡 ClickHouse TTL deletion runs asynchronously during merge operations. Data may persist slightly longer than the TTL value. This is expected behavior.

👥 User Management

Users are managed through the Users page in the pktFlow dashboard (admin login required) or directly via the SQLite database.

From the Dashboard

  • Navigate to Users in the sidebar
  • Click Add User to create a new account
  • Click a user's name to edit their role or reset their password
  • Deactivate users with the toggle — deactivated users cannot log in

Roles

RolePermissions
adminFull access — all data, settings, user management, service restart
analystRead all data, export flows, acknowledge alerts
viewerRead-only access to dashboard pages

Emergency Password Reset (CLI)

If admin access is lost, reset a password directly in SQLite:

python3 - <<'EOF'
import sqlite3, bcrypt
conn = sqlite3.connect('/opt/pktflow/pktflow.db')
new_hash = bcrypt.hashpw(b'NewPassword1!', bcrypt.gensalt()).decode()
conn.execute(
  "UPDATE users SET hashed_password=?, is_active=1 WHERE username='admin'",
  (new_hash,)
)
conn.commit()
conn.close()
print("Password reset complete")
EOF
⚠️ The is_active=0 flag silently rejects login with "Invalid credentials." Always check and set is_active=1 when doing a CLI password reset.

📝 API Reference

pktFlow exposes a REST API. All endpoints except /api/ingest/* require a JWT Bearer token (obtained via POST /api/auth/login).

MethodEndpointDescription
POST/api/auth/loginGet JWT token. Body: {username, password}
POST/api/ingest/flowsIngest flow batch. Auth: Bearer ingest token. Body: JSON array of flow objects.
GET/api/ingest/statsReturns ingest counters (total_received, total_flushed, last_flush)
GET/api/flows/queryQuery flows with optional filters: src_ip, dst_ip, src_port, dst_port, proto, site, start, end
GET/api/flows/top-talkersReturns top N source IPs by bytes in time range
GET/api/alertsList alert events
GET/api/usersList users (admin only)
POST/api/usersCreate user (admin only)

💾 Backup & Recovery

What to Back Up

  • config.yaml — system configuration including keys
  • pktflow.db — SQLite database (users, settings, alert rules)
  • pktflow.service — systemd unit file
  • ClickHouse data (for flow history): use clickhouse-backup or filesystem snapshot

Restore Procedure

1

Stop the Service

systemctl stop pktflow

2

Restore Files

Copy backed-up config.yaml and pktflow.db back to the application directory.

3

Restore ClickHouse (if needed)

Use clickhouse-backup restore or restore the data directory from a snapshot.

4

Restart and Verify

systemctl start pktflow, then check /api/ingest/stats and the dashboard.

pktFlow Style Guide

The complete reference for building pktFlow companion apps. Copy the base CSS template, follow the component patterns, and your UI will match the pktFlow visual language exactly.

🎨 Design Tokens

Every color, radius, and semantic value is defined as a CSS custom property. Always reference tokens — never hardcode hex values in app code.

CSS Variables — paste into your :root {}
:root {
  /* Core backgrounds */
  --bg-primary:   #111827;   /* page background            */
  --bg-card:      #0d1f3d;   /* card, panel, sidebar       */
  --bg-surface:   #1a2744;   /* elevated / hover surface   */
  --bg-deep:      #0a1628;   /* inset wells, code blocks   */

  /* Accent */
  --accent:       #60a5fa;   /* highlights, links, icons   */
  --accent-dim:   #3b82f6;   /* buttons, interactive       */

  /* Text */
  --text-primary:   #ffffff;
  --text-secondary: #9ca3af;
  --text-muted:     #6b7280;

  /* Borders */
  --border:         #1e3a5f;
  --border-accent:  rgba(96,165,250,0.3);

  /* Semantic */
  --success:  #22c55e;
  --warning:  #f59e0b;
  --danger:   #ef4444;
  --info:     #60a5fa;

  /* Border radius scale */
  --radius-sm:  6px;
  --radius-md:  10px;
  --radius-lg:  14px;
  --radius-xl:  16px;
}

Callouts

Four semantic variants. Each uses a transparent tinted background with a matching border. Use for tips, notes, warnings, and critical alerts in docs.

ℹ️Info: Used for context, reminders, or clarifications that readers should know.
💡Tip: Best practices, shortcuts, and pro advice. Green = positive / helpful.
⚠️Warning: Something to watch out for. Yellow = caution but not blocking.
🚨Danger: Security-critical or data-loss risk. Only use when something will break.
/* Base callout */
.callout {
  border-radius: var(--radius-md); padding: 1rem 1.25rem;
  display: flex; gap: 12px; align-items: flex-start; font-size: 0.9rem;
}
/* Variants — swap color values */
.callout.info    { background:rgba( 96,165,250,0.08); border:1px solid rgba( 96,165,250,0.25); color:#93c5fd; }
.callout.tip     { background:rgba( 34,197, 94,0.08); border:1px solid rgba( 34,197, 94,0.25); color:#86efac; }

function openModal() {
  document.getElementById('my-modal').classList.add('open');
  document.body.style.overflow = 'hidden';
}
function closeModal(e) {
  if (e.target === document.getElementById('my-modal')) {
    document.getElementById('my-modal').classList.remove('open');
    document.body.style.overflow = '';
  }
}
document.addEventListener('keydown', e => {
  if (e.key === 'Escape') {
    document.getElementById('my-modal').classList.remove('open');
    document.body.style.overflow = '';
  }
});

⛔ Hard Rules

These are non-negotiable for visual consistency across all pktApps.

⛔
Never use <img> for SVG files.
SVG gradients and filters break when loaded via img from the filesystem. Always inline the SVG markup directly in the HTML.
⛔
Never hardcode hex colors in app CSS.
Always use CSS custom properties (var(--token-name)). This ensures a single source of truth and makes future rebranding possible.
⛔
Never load external fonts.
Use the system font stack only. No Google Fonts, no @font-face. Native fonts keep pages fast and visually consistent across OS.
⛔
Never use a white or light background.
pktFlow is a dark-first design system. The lightest surface is --bg-surface (#1a2744). No section, card, or modal should use a light background.
⛔
Never introduce a second accent color.
The only non-semantic color is blue (#60a5fa / #3b82f6). Semantic colors (success, warning, danger) are for status indicators only — not decorative use.
⛔
Never skip the SVG id namespace when combining diagrams.
If two inline SVGs appear on the same page, their <defs> ids must be unique (e.g. id="glow-flow" vs id="glow-arch"). Shared ids cause one diagram to steal the other's defs.
✅
Do: start from the Base CSS Template.
Copy the Base CSS block from the section above as your starting stylesheet. Add your app-specific rules below it. Do not rewrite what's already defined.
